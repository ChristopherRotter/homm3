## ADR-0016 (the adventure state), point 3 (a hero on the map)

Add to the hero on the map's fields: **its place in its owner's list of heroes** (`listed`, from
0). An owner's heroes on the map hold the places 0 to n − 1 in the order they joined the map; a
town's garrison heroes are in no list (their place 0, unhashed). The adventure sets the place
whenever a hero joins the map (a caller's value replaced): the setup's heroes take theirs in the
setup's order, each hero that joins later (a hire, a garrison hero stepping out, a freed prisoner)
the end; a hero that leaves the map (a battle's loser, a retreat or surrender, a dismissal, a
visitor going into a garrison) leaves it and the heroes after it move up, so a state's list has one
encoding. The state hash holds each hero on the map's place (adventure state hash v28).
`AdventureState::hero_list(player)` and `listed_hero(player, n)` read it.

## ADR-0017 (the game's orchestration)

- **Point 4 (the build):** the game hands the adventure its heroes in the start list's order: each
  player's placed heroes by hero type (a random hero by its drawn type), then the main towns'
  generated heroes in player order (GAM-SET-004, the original's `placed_heroes_setup` and
  `main_town_heroes`). The heroes' ids stay the setup's; the prisoners are in no list.
- **Point 8 (the observation):** the viewer's observation carries its list of heroes
  (`GameObservation::hero_list`); the wire's (protocol v81) and the protocol's fold keep it from
  the viewer's heroes on the map (one that left leaves it, one that came joins its end).
- **The env (ADR-0025's adventure encoding, the AI lane's):** a player's hero slots are its list's
  first eight places (action encoding v20).
