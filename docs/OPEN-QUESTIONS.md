## Open

### Q2 — Project name and crate prefix

The repo is `homm3`; crates use the provisional prefix `h3-`. "Heroes of Might and Magic" is a trademark of its owner; a public project name should probably avoid implying endorsement. Decide before first public release; renaming later is cheap but not free.

### Q4 — Confirm local compute

### Q5 — RL implementation language/framework

Deferred. Options later: Python + PyTorch (ecosystem), Rust-native (burn/candle), or other via C ABI. Decide when E05/E06 are refined. Note the GTX 1070's Pascal architecture may constrain framework/CUDA versions.

### Q7 — Supported platforms for the core

Proposed: native Windows, Linux, macOS and WASM compile targets for the logic crates; CI initially Linux + Windows. Confirm.

### Q10 — Multiplayer model confirmation

Design assumes **authoritative server with per-viewer projections** (`06-security.md`); lockstep with full state is excluded because it leaks hidden info. Confirm this matches intent for any future multiplayer.

### Q22 — Jousting: path length or start-to-end distance (E03 T5)

Wiki (Cavalier page): the bonus is "calculated based on the distance between starting and ending positions". VCMI passes the length of the path actually walked. They differ when obstacles or stacks force a detour. **Implemented: path length (VCMI)** (BAT-DMG-005). **Experiment:** place a Cavalier so that its shortest path to the target detours around an obstacle (e.g. 5 steps for a straight distance of 4); compare its damage on a fixed target with a 4-step straight charge (+25 % vs +20 % of base).

**Not in batch 1a** (2026-10-03): the experiment needs a controlled detour and, because Champion damage is random, many repetitions. If a task needs the answer, reading the game's code is the cheaper last resort (Q29); otherwise VCMI's path length stays.

- *(2026-10-04, Q31, E04a T4b start)* **What a scenario is, and what the battle checks of a hero.** A scenario (`packs/*/scenarios/*.toml`) is a battle-setup file for tests, the CLI, benchmarks and the sim, not a game round. The user: "the battle context should not be concerned with 'accuracy' of hero values; it is fed whatever the game state happens to be." **Decision:** the battle takes the `BattleHero` as given and checks only what its rules need to run soundly (references of the ruleset, list sizes, values in the ranges where its rules and arithmetic are defined); values no real hero could have (primary skills above 99) are accepted. Keeping values within the game's limits is the derivation's job (HER-BAT-001). Scenario files, and the replays recorded from them, give a side's battle hero **directly**, without derivation; deriving it from hero details stays with the game orchestrator (E08+) and the experiment tool (T11). Scope of the session: T4b split into T4b1 (types and derivation) and T4b2 (the seam switch), both delivered as separate checkpoints.

- *(2026-10-03, Q23, experiment batch 1a R1–R3)* **Damage rounding: the original uses the single-precision values of its rates.** Observed (SoD, `experiments/results/E04a-batch-1a.md`): Archangels with +22 attack points deal 105/210/…/630 (= exact), Angels with −24 points 19/39/…/119 (exact would be 20/40/…), Archangels against Basic Armorer 47/94/142/189/237/284 (exact 47/95/…/285). All 18 values match one model: exact arithmetic with the binary single-precision values of 0.05 (13421773/2^28), 0.025 (13421773/2^29) and the skill table's fractions, rounded down once; storing the factor in single precision (x87s) and single-precision arithmetic throughout (f32) are excluded; double or extended intermediate precision cannot be told apart and does not matter outside 2^-50 of an integer. This also explains the wiki's Armorer example (S-02). **Consequence:** quirk Q-0005 (class fix-optional, confirmed by the user 2026-10-03; one flag for all damage rates, faithful = single-precision values, strict-fixed = exact rates); implemented by E04a T6a (flag `quirk.battle.single_precision_rates`), computed exactly in integers (no floats, ADR-0003).
- *(2026-10-03, Q21, experiment batch 1a R4)* **Death stare: the new top creature has full health (wiki).** Observed: 40 Ogres (top 40 HP) take 333 damage (8 die, the top Ogre would be at 27 HP) and 2 death-stare kills: 30 Ogres remain with the top at 40 HP.
